# ローカルECGモデル開発ロードマップ

この文書は将来の研究・検証計画です。現在、検証済みローカルECGモデルは未搭載であり、臨床利用可能な自動抽出機能を示すものではありません。

## 入力と前処理

- 入力形式はJPEG、PNG、WebP。匿名化済みの12誘導心電図画像を対象とする。
- 標準的な3×4、6×2、連続リズムストリップ付きレイアウトを候補とし、レイアウト不明を明示的に扱う。
- 元画像は保持し、切り抜き、90度回転、縮小、形式変換の処理後画像と比較可能にする。
- 前処理候補はグレースケール、コントラスト評価、傾き推定、台形歪み検出、用紙領域・グリッド検出。破壊的な自動補正は行わない。
- 誘導名・校正波形・紙送り速度・感度を検出し、各誘導を分割する。分割失敗と誘導不明を判定不能として出力する。

## 教師データと対象所見

- 教師データは画像、患者単位ID、機器・施設、画質、誘導配置、専門医合議ラベル、測定根拠を含む定義書で管理する。
- 対象候補は心拍数、リズム、P波、PR、QRS、QT/QTc、軸、R波進行、Q波、ST、T波、U波、PVC、R on T、脚・房室ブロック、ペーシング、電極装着異常。
- OCRは印字された数値、単位、誘導名、紙送り速度、感度の候補抽出だけに使用し、波形実測や診断確定として扱わない。
- 正常値を欠測項目へ補完せず、各項目に`value | null`、confidence、判定不能理由を持たせる。

## 出力Schema

- 既存`EcgImageAnalysisResult`との互換層を設け、モデルバージョン、前処理バージョン、backend、画質、測定値、所見、項目別confidence、limitationsを返す。
- 数値の単位、許容範囲、null、enumをSchemaで固定する。
- 診断候補はモデル出力に含めず、医師確認後の所見を既存ローカルルールエンジンへ渡す。

## 学習・検証設計

- 学習、内部検証、時間的検証、施設外部検証を分離する。
- 同一患者の複数画像が異なる分割へ混入しないよう、患者単位で分割する。
- 施設、装置、撮影条件、疾患頻度の偏りを記録し、クラス不均衡には重み付け・層別評価を用いる。
- 所見ごとに感度、特異度、PPV、NPV、AUROC／AUPRC、校正、判定不能率を報告する。
- 画質、反射、傾斜、解像度、レイアウト、機種、施設別に性能を評価する。
- 医師間一致度とモデル対合議ラベルの差を評価し、患者アウトカムを未検証のまま診断精度と表現しない。

## ブラウザ配布

- 学習済みモデルをONNXへ変換し、元モデルとの数値一致と演算子互換性を確認する。
- FP16／INT8量子化は精度低下、モデルサイズ、初期化時間、推論時間を比較して採否を決める。
- WebGPUを第1候補、WASMをCPUフォールバックとし、Chrome／Edgeの複数世代・GPU・メモリ条件で試験する。
- 端末別に初期ロード、前処理、推論、後処理、ピークメモリ、発熱、失敗率を測定する。
- モデル、前処理、出力Schema、検証レポートを独立にバージョン管理し、manifestとハッシュを配布する。
- 配布ライセンス、Git LFS、Vercel配信上限、同一オリジンキャッシュ、更新時のキャッシュ無効化を確認する。

## 運用上の検討事項

- 医療機器プログラムへの該当性、使用目的、対象利用者、適応範囲、禁忌、責任分界、変更管理、サイバーセキュリティ、監査記録を専門家と検討する。
- 未検証モデルを臨床利用可能と表示しない。検証終了後も医師確認、判定不能、モデル限界、バージョンを画面に明示する。
- 本番導入前に前向き評価、ヒューマンファクター評価、障害時の手入力経路、ロールバック手順を整備する。
